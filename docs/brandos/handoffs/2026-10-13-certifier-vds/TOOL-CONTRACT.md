# Tool contract
1. **Allow-list in code.** The runner registers exactly the 5 tools in `TOOLS.json`. Any other tool name in a model response → call dropped, logged as `forbidden_tool`, run continues; a name in `forbidden_tool_names` also flags the run for review. Test: zero tool calls outside the list.
2. **Scope.** Every tool is bound server-side to `{workspaceId, brandId, bioId, runId}` from the run record — never from model arguments. `read_source` with an id outside the manifest → `{error:"unknown_source"}`.
3. **Read-only DB access.** Reads use a query helper that only issues `select` (no `supabaseAdmin.from(..).update/insert/delete` in `server/src/lib/certifier/*`; enforced by a lint test grepping the folder). The only write is `draft_client_question` → insert into `certifier_question_drafts` with `status='draft'` (new table, S2 migration — do not apply/seed here).
4. **Never sends.** `draft_client_question` has no notification side-effect. Sending is the CD's action in S3 (`POST /api/steward/certifier/:runId/questions/send`, human actor, one batch per section, sent under the CD's name).
5. **Server rejects certification by an agent.** Every certify path — `POST /api/bios/:brandId/self-certify` (`routes/bios.js:398`), `PATCH /api/steward/jobs/:id` (`routes/steward.js:169`), `POST /api/steward/decertify` (`routes/steward.js:393`) and the new per-claim confirm endpoint — calls `assertHumanActor(c)`: if the request carries an agent/service token (`auth.actorType === "agent"` or a delegation token from `lib/delegation-token.js`) → **403 `AGENT_CANNOT_CERTIFY`**. Agent runs never receive a user JWT. Test: call each endpoint with an agent token → 403, no row change.
6. **Limits.** ≤6 read calls; `search_sources` limit ≤10; `read_source` ≤8k tokens per call; total cost cap $0.30 aborts the loop.
7. **Audit.** Every tool call logged to the run log (name, args hash, latency, bytes).
